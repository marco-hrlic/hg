# graph-adlc v0.3 — LLM-assisted graph maintenance: results

**Date:** 2026-11-03 · **Engine:** graph-adlc 0.1.0, unchanged · **Layer:** `graph_adlc/llm_graph/` · **Oracle:** v1.0, single reviewer, exploratory · **Prompts:** frozen in `prompts/PROMPTS.lock.json`

This file is generated by `evaluation/llm_graph/report.py` from `out/*/metrics.json`. Interpretation is in the sections marked *Reading*.

## Bottom line

* **No language model was evaluated.** No model credentials were configured in the environment where this milestone was built, so the live arms (D, and G1/G2 with a real model) were **not run**. RQ1 (construction fidelity), RQ2 (maintenance fidelity) and RQ3 (influence benefit versus a document-only model) are therefore **not yet evaluated**. Nothing below is a measurement of model quality.
* **What was built and verified:** an end-to-end, opt-in maintenance loop over the existing engine — source snapshots (files and immutable Git commits) → model proposal → citation/provenance validation → per-operation human review → `GraphADLC.propose`/`commit` → spec-only Markdown → influence before/after — plus a missing-edge challenge, an evidence-sufficiency gate, a live provider adapter and a deterministic scripted fake. The loop ran **5 events on one persistent graph per project and arm** for two independently written projects; all 15 acceptance cases (L01–L15) have passing tests.
* **What the deterministic parts show** (these do not depend on the fake):
  * The deterministic import scan recovered the code-only dependency in both projects (toolshare `CMP-HOLDS → CMP-NOTIFY`: recovered; ledgerlite `CMP-CSV → CMP-MONEY`: recovered), with verified line-level citations into the commit that introduced it, before the impact question was asked.
  * **SC-14 reproduced on independent material.** In ledgerlite, a `contract_preservation` record that passed, was current, and covered only amounts below 1000 lets the unchanged v0.1 engine prune CMP-CSV, CMP-PDF; the critical consumer CMP-CSV is among them. The new coverage gate refused that record (1 refused, 0 admitted), so the gated condition prunes nothing. Pruning stays off by default.
  * **Every arm, including the curated reference graph H, misses REQ-CSV-EXPORT.** The engine's `check_contract` on a consumer component is terminal, so a broken consumer never reaches the requirement it implements. This is the v0.2 'premature terminal propagation' class again, now on a code-discovered dependency; better graph maintenance cannot fix it.
  * Wording-only edits: without the maintenance loop, the engine has no editorial aspect and raises 3 (toolshare) and 2 (ledgerlite) obligations on the reference graph. With the loop, an editorial change is either recorded as a `no_change` or held in quarantine for review instead of being committed.
* **Recommendation:** run the frozen live protocol (`--mode live`) with a configured model before building anything else; separately, decide whether `check_contract` on an implementing component should reach the requirement it implements (a versioned engine change with its own before/after).

## 7. Notable failures (case by case)

1. **ledgerlite E5: `REQ-CSV-EXPORT` missed by every arm (critical).** The path `CMP-MONEY` → (depends_on) → `CMP-CSV` ends at a terminal `check_contract`, and the rule table has no step from a checked consumer component to the requirement it implements. Source: the DR-001 criterion 'no thousands separators' versus c3 `money.py`, where `f"{q:,} {currency}"` is used by `csv_export.py`.
2. **ledgerlite E5: `TEST-MONEY-FORMAT` missed by every arm.** An implementation-aspect change to a component does not reach tests that verify its contract. The test's sample table (all < 1000) is exactly why the preservation evidence was insufficient.
3. **SC-14 recreated.** The engine pruned the critical consumer on passing, current, incomplete evidence (section 3, exploratory pruning). The v0.3 gate requires declared coverage of the change's declared input domain. Without a declared domain, nothing is admissible.
4. **Wording-only changes have no engine representation.** The safe handling is procedural (a `no_change` record or quarantine). If a reviewer accepts an editorial `update_node`, it still propagates as a semantic change.
5. **Lifecycle quirk.** `reconcile --rebase` on an `active` work unit fails ('active -> active'), so the replay rebases only invalidated units.

## 10. Recommended next step

Run the frozen protocol live: set `GADLC_LLM_MODEL=<id>` and either `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` (`GADLC_LLM_PROVIDER` picks one if both are set), then `python evaluation/llm_graph/run_replay.py --mode live && python evaluation/llm_graph/score.py --run evaluation/llm_graph/out/live && python evaluation/llm_graph/report.py`. Have someone other than the fixture author label the E5 impacts first. It is the cheapest experiment that can actually answer RQ1–RQ3, and the harness, prompts and scoring are already frozen. Separately (and versioned), test an engine rule letting `check_contract` on an implementing component raise `review_implementation` on its requirement, because the reference graph shows that maintenance alone cannot recover those critical misses.
